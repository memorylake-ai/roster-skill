# 概念

## 员工

一名数字员工 = 一个 IM 账号 + 一个大脑 + 它的设置（岗位说明、技能、记忆、群聊回应、自动任务）。员工在用户自己的电脑上运行，电脑关机它就不在线。

- **名字**：`name` 是目录名（命令里用它），另有显示名。命令里两者都认。
- **状态**：运行中 / 已停止 / 需要处理。`rosterctl status --json` 的 `headline` 是一句人话的现状。
- **回收站**：`employee recycle` 移进回收站，`employee restore` 恢复；彻底删除只能人做。

## IM 平台

| 平台 | 说明 |
|---|---|
| 钉钉（真人账号） | 员工用一个真实钉钉账号办公，能读群消息、文档、日程等；建好后需要人设置主管 |
| 钉钉（机器人）、飞书、企业微信 | 扫码建一个机器人应用；扫码的人就是主管 |
| 微信 | 扫码接入；只和扫码的人单聊 |
| Slack、Telegram | 用户在自己的工作区 / BotFather 建应用，在界面里填授权 |

不同平台能做的事不同（比如只有部分平台能读群里不 @ 它的消息）。命令或员工说「这个平台做不到」时，如实转告用户，给出替代做法。

接入新账号一律需要人（扫码或填密钥）：`rosterctl im connect <平台> --json` 会返回要打开的页面。

## 大脑

员工用哪个 AI 干活：Claude Code、Codex、OpenCode、DeepSeek、Hermes、Pi 等，以 `rosterctl model list --json` 列出的为准（只列本机装好、能用的）。
模型的 key 由用户在界面里填；`rosterctl model test <模型> --json` 真调一次验证。

## 主管

员工的主管是能给它下敏感指令、审批它的操作、接收它汇报的人。主管只能人设、人改。

## 群聊回应

每个群一张规则表：谁说话、怎么说（@ 它 / 不 @ / 包含关键词）时，员工**回复**、**运行某个自动任务**还是**忽略**。
`rosterctl group list <员工> --json` 看现状；`group set` 改一个群（先 `group list` 拿到 `rev`，改的时候带上；退出码 5 = 期间被改过，重新读）。
单聊可以设成只回复指定的人。

## 权限

员工做事时遇到敏感操作（写文件、执行命令、对外发消息）会按权限规则拦下来，请主管放行。放开权限只能人在界面里做。

## 技能

员工可以装技能（比如读写文档、查数据）。`rosterctl skill list <员工> --json` 看已有技能与开关；`skill enable / disable` 开关。
需要填凭据的技能，打开时会交给人。从技能库安装新技能目前在界面里做。

## 记忆

员工可以有自己独立的长期记忆空间（由 MemoryLake 提供）。`rosterctl memory status --json` 看记忆服务是否已连接；
`rosterctl memory enable <员工> --json` 给员工开通。连接记忆服务（填 key、登录）需要人。
