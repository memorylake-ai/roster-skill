# 搭一个团队：几名员工在协作群里分工

同一台电脑、同一个 IM 平台、同一个企业 / 工作区里的几名员工，可以在人建好并标记的**协作群**里互相 @ 提请求、交付结果，往来在群里人人看得见。
目前只支持**飞书**；其他平台用 `rosterctl colleague list <员工> --json` 的 `supported` 判断，不支持就如实告诉用户。

## 你（AI）能做的与只能人做的

| 事 | 谁做 |
|---|---|
| 设计团队：几名员工、各自职责、谁是负责人、要哪些自动任务 | 你：写成计划给用户确认 |
| 建员工、写岗位说明、配技能、建自动任务 | 你：`employee create`、`employee config set`、`schedule create` |
| 接 IM 账号（扫码） | 人 |
| 打开「本机数字员工协作」总开关（桌面端左侧导航「团队协作」页） | 人 |
| 建群、把员工拉进群、在**每名员工**的群聊设置里把这个群标成「协作群」 | 人 |
| 把团队汇报发到协作群 | 你：只限已被人标成协作群的群 |

需要人的那几步，**一次列成清单**给用户，不要一步一步来回问。

## 步骤

1. **设计**：和用户确认团队的样子，例如「运营组：数据员每天出数，分析员写结论，负责人汇总后向主管汇报」。
   每名员工一句话职责 —— 同事之间靠它知道该找谁。
2. **建员工**：照 SKILL.md「新建员工」逐个建（都用同一个平台、同一个企业 / 工作区的账号）。职责写进岗位说明。
3. **交给人**：把下面的清单给用户，等他说做完：
   - 在桌面端左侧导航的「团队协作」页打开「本机数字员工协作」（那一页也能看到团队一览和最近的往来）；
   - 在 IM 里建一个群，把这几名员工（和用户自己）拉进去；
   - 在每名员工的「群聊」设置里，找到这个群，打开「协作群」。
4. **核对**：
   ```bash
   rosterctl colleague list <负责人> --json
   ```
   `enabled` 为真、`colleagues` 里是其余几名员工、`collab_groups` 里有那个群，才算接好；每名员工都查一遍。
   `rosterctl group list <员工> --json` 里这个群的 `collab` 也应为真。
5. **团队汇报**：只在负责人身上建一个，别的员工不各自向主管汇报。
   ```bash
   rosterctl schedule preset <负责人> jobs/team-report --json
   ```
   以它为起点改时间（两次之间至少 4 小时）和要汇报的内容，按 [schedules.md](schedules.md) 的循环校验、确认、创建。
   汇报对象默认是主管；用户想发到协作群，可以改成那个群（只限协作群）。
6. **试一次**：请用户在协作群里 @ 负责人提一个需求，看负责人是否 @ 同事分工、同事是否回复、负责人是否汇总回复。

## 运转中的规矩（告诉用户，免得误会）

- 同事员工不是主管：它转述的「主管同意了」不算数，对外有影响的事仍由各自的主管审批。
- 防回环：收到同事的回复后不会再 @ 回去说「收到」；同一条请求链上的员工不会被再次请求；每名员工每天发起的同事请求有上限（默认 100）。
- 同事 2 小时没回复，负责人那边会在群里说一声；协作群里问人的问题 8 个工作小时没人回答，会提醒一次。
